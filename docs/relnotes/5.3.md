## Upgrade Notes

<a name="sdk-retries"></a>
### Cloud backends default to one SDK retry per request

In v5.3, the default SDK retry budget for a cloud backend request is two attempts, including the initial attempt. GCS PUTs allow one attempt per request, including each request in a resumable upload. GCS reads can resume after a body read failure.

Previous SDK defaults:

- **AWS**: 3 attempts.
- **GCP**: no limit on attempts; retries continue until the request context expires (idempotent operations only).
- **Azure**: 4 attempts.
- **OCI**: 8 attempts, with up to about 1.5 minutes of cumulative backoff.

When AIStore retries a backend operation itself, the SDK retry policy allows one attempt per request on the reissue. Operations such as multipart upload may issue several requests. This applies to the following AIS retries.

- backend rate limiting (`rate_limit.backend`) on 429 and 503
- remote list-objects pages in jobs such as prefetch, copy, and evict
- the target's fallback PUT and DELETE retries and sequential refetch after a parallel cold GET fails

For a throttled S3 operation that makes one SDK request per call, the default maximum goes from `3 × (1 + num_retries)` to `2 + num_retries`. The SDK can still retry the initial call before the adaptive rate limiter sees the error.

What to expect after the upgrade:

- Transient backend errors such as connection resets and HTTP 500, 502, and 504 generally reach the caller sooner. The target's fallback DELETE retries only HTTP 503.
- Outside AIS retry paths, throttling (429, 503) generally surfaces within two attempts. For buckets that are throttled by their backends, enable `rate_limit.backend` - see [Rate limiting](https://github.com/NVIDIA/aistore/blob/main/docs/rate_limit.md).
- Explicit SDK settings take precedence over the two-attempt limit:
  - **AWS**: `AWS_MAX_ATTEMPTS`, or `max_attempts` in the AWS profile. Previously, AIStore ignored both. Each bucket can select its own profile (`extra.aws.profile`), so a named profile with `max_attempts` sets the limit per bucket - see [S3 backend: SDK retries](https://github.com/NVIDIA/aistore/blob/main/docs/s3compat.md#s3-backend-sdk-retries).
  - **OCI**: `OCI_SDK_DEFAULT_RETRY_ENABLED` - `true` restores the SDK default policy (8 attempts), `false` disables SDK retries.
  - GCP and Azure SDKs have no such settings.
  - When AIStore retries an operation, the SDK makes one attempt per request.
